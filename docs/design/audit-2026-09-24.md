# Frontend audit — 2026-09-24

The audit that preceded the enterprise design-system pass (ADR 0048). It
records what was found, what was fixed on branch `design/enterprise-system`,
and what is left, so the next pass starts from facts rather than impressions.

Method: source read of `resources/js` and `resources/css`, token and class
usage counted with grep, and the running admin (`http://infracms.test`)
inspected in Chrome in dark and light themes at 1920, 1440, 1366 and 1280
CSS-pixel widths.

## 1. What the project is

| Area | Finding |
| --- | --- |
| Framework | Laravel 13 + Inertia + Vue 3.5 (`<script setup lang="ts">`), Vite 8 |
| CSS | Tailwind v4 via `@tailwindcss/vite`; tokens as custom properties in `resources/css/app.css`, mapped into `@theme` |
| Component library | None, by decision (ADR 0040). ~30 owned primitives in `resources/js/Components` |
| Icons | Phosphor (`@phosphor-icons/vue`), `regular` weight, concept map in `icons.ts` — one family, used consistently |
| Routing / layout | Inertia pages under `Pages/Admin`, `Pages/Client`, `Pages/Auth`; `AdminLayout` (rail + topbar + breadcrumbs), `ClientLayout`, `AuthLayout` |
| Theme | Light / dark / system (`useTheme`, `data-theme`), density presets (`data-density`), brand overrides (`useBranding`), three theme manifests (only Core built) |
| Tables | `AppTable` with column visibility, selection, bulk bar, skeleton; rows are caller markup |
| Forms | `AppInput/Select/Textarea/Checkbox`, `MoneyInput`, `CustomFieldInput`, `AppRichText` |
| Dialogs / drawers | `AppConfirm` (confirmation ladder), `AppDrawer`, `OperationsDrawer`, `CommandPalette` |
| Charts | `AppBarChart` (SVG-free CSS bars with an `sr-only` table) |
| Tests | Vitest + happy-dom, 85 tests at the start (layout, table, a11y, drawer, confirm, palette) |

The foundation was better than typical: a real token layer, a written design
document, a status component with shapes, an accessible confirmation ladder,
teleported menus that escape overflow. The problems were in **how screens
were composed**, in **drift between screens**, and in **a handful of bugs in
the token layer** that made several intended styles silently not apply.

## 2. Findings

### Bugs in the token layer (fixed)

- `app.css` referenced `--color-surface`, `--color-surface-sunken` and
  `--color-surface-raised`, none of which existed. Result: the body had no
  background of its own, table rows had **no hover colour**, the skeleton had
  no fill, and the sticky table header was **transparent** (rows scrolled
  visibly under it).
- `AppButton` put `border-transparent` in its base classes, which beat the
  secondary variant's `border-line`: **secondary buttons had no visible edge**.
- `<meta name="color-scheme" content="light dark">` with no CSS override meant
  native controls followed the OS, not the chosen theme — **black checkboxes
  in Light mode** on a dark-OS machine.
- The density tokens (`--row-y`, `--control-y`, `--card-p`) were defined and
  **read by nothing**; density presets changed no measurement.

### Consistency and drift

- **Status**: 25 pages each had a local `tone()`; they disagreed (closed
  customer red vs closed ticket grey; expired domain red on its list, amber on
  its page; refunded invoice green; cancelled order red). Status rendered as a
  tinted `AppBadge` — **colour alone**, against Handoff §7 and the project's
  own design document. (Fixed: `resources/js/status.ts` + `AppStatus`
  everywhere; see §3.)
- **Type**: 578 uses of Tailwind's `text-xs`/`text-sm` beside the project's
  scale; `text-sm` is 14px, so form labels were larger than the 13px body.
  Headline figures at arbitrary `text-[1.375rem]`/`[1.5rem]`/`[1.625rem]`.
- **Radius**: 125 arbitrary `rounded-[var(--radius-*)]`; buttons and inputs
  used the 6px badge radius instead of the 8px control radius.
- **Control heights**: inputs ~42px, buttons ~38px, selects ~42px — no row of
  mixed controls lined up.
- **Icon sizes**: 11, 12, 13, 15, 16, 17, 18, 20px in use.

### Composition (anti-patterns)

- **Card per region.** Dashboard: five cards stacked, a chart titled twice
  ("Money in" / "Money in, by month"). Client detail: a 2×2 grid of cards with
  large empty areas.
- **A search page instead of a filter bar.** Clients list: two rows of
  labelled fields (≈150px) above four rows of data, misaligned because one
  field had a hint and the others did not; First name, Last name and Name as
  three columns saying one thing.
- **No pagination on the Clients list**: only "Page 1 of N" text — no way to
  reach page 2 from the UI.
- **Fixed footer** taking ~36px from every screen to repeat a copyright line.

### Dangerous operations

- Client detail: **"Erase personal data" as a solid red button beside Edit**
  in the header, opening an inline card with a checkbox.
- **Delete contact: one click, no confirmation.**
- **Uninstall module, delete canned reply, turn off a staff member's 2FA,
  turn off your own 2FA: one click, no confirmation.**

### Accessibility

- `AppConfirm` and `AppDrawer` declared `aria-modal` but **did not trap
  focus**; Tab left the dialog.
- `AppTextarea` errors and hints were not linked with `aria-describedby`
  (inputs and selects were).
- Status as colour-only badges (above).

### Data/copy observations (not changed — server side)

- The dashboard activity feed is dominated by "Superadmin bypass" audit rows,
  which pushes meaningful events off the list. Consider excluding bypass
  records from the dashboard query, or grouping them.
- Customer tax number renders as `-` from the server for empty values while
  the UI uses `—`.
- Modules page shows a raw translation key, `modules.types.infrastructure.label`,
  as the File Probe module's type badge.

## 3. What was done

**Tokens / CSS** (`resources/css/app.css`): undefined tokens fixed;
`--control-h`/`--control-h-sm` added per density; `--row-y` now pads every
`.data-table` cell via zero-specificity `:where()`; `color-scheme` pinned to
the explicit theme; `.tab-list` baseline.

**Primitives changed**: `AppButton` (control height, `icon` prop,
`danger-subtle` variant, border fix), `AppInput`/`AppSelect`/`AppTextarea`
(control height, type scale, textarea `aria-describedby`), `AppStatus`
(`neutral` tone), `AppTable` (sortable headers with `aria-sort`,
`hideBelow`, `sticky`, columns control in the header row, density padding),
`AppAlert` (tone on edge/icon, text stays readable), `EmptyState` (`plain`
variant), `AppBarChart` (`hide-title`), `AppConfirm`/`AppDrawer` (focus trap),
`AdminLayout` (`PageHeader` with `#status`/`#meta`/`#header`, footer in flow).

**Primitives added**: `PageHeader`, `DetailSection`, `DescriptionList`,
`AppTabs`, `FilterBar`, `SearchInput`, `FilterSelect`, `MetricStrip`,
`LoadingState`, `ErrorState`, `useFocusTrap`, `status.ts`.

**Representative pages redesigned** (props and server contracts unchanged):

| Page | Template | What changed |
| --- | --- | --- |
| `Admin/Dashboard` | overview | Sections not cards; one-line "nothing needs attention"; `MetricStrip`; revenue + infrastructure side by side; activity as a table; environment/version in the meta line |
| `Admin/Customers/Index` | list | `FilterBar` (search, email, status, group, More filters with a count, Clear only when filtered); meta line with count; `AppStatus`; duplicate name columns off by default; sticky name column; priority columns; working pagination; filtered vs. empty states |
| `Admin/Customers/Show` | detail | Identity header with status and copyable ID; tabs Overview / Contacts / Notes (deep-linkable); contacts as a table with hover row actions; erase moved to the Danger Zone behind a destructive confirmation (reason + typed name); contact removal and portal impersonation confirmed |

**Propagated across the app**: type scale (578 replacements), radius utilities
(125), status vocabulary (41 more pages, including inline-ternary and
toneless status badges on invoices, orders, tickets, servers and the catalog;
words added to `status.ts` from the PHP enums: `failing`, `transferring`,
`payment_review`, `fraud_review`, `partially_fulfilled`, `on_hold`, `full`,
`unreachable`, `hidden`, `retired`, `withdrawn`, `unbilled`), confirmations
on the four unconfirmed destructive actions.

Colour changes this caused on purpose: refunded invoice green → neutral;
cancelled order red → neutral; closed staff account red → neutral; expired
domain amber → critical on client pages and admin domain detail; ignored /
duplicate gateway events and suppressed notifications amber → neutral;
retrying / provisioning / registering amber → info.

**Tests**: 85 → 103 (status vocabulary, tabs keyboard/ARIA, sortable headers,
responsive column CSS, focus trap). Typecheck, lint and build pass.

## 4. Still to do (propagation list)

The per-page, prioritised checklist is `docs/design/propagation.md`; the
conversion recipe is `.claude/skills/frontend-architecture/page-recipes.md`.
The reference screens and the new primitives are translated (`lang/*/ui.php`,
published through `FrontEndTranslations`). The summary, in priority order:

1. **Detail pages to the Customer pattern** — `Services/Show`, `Domains/Show`,
   `Orders/Show`, `Invoices/Show`, `Resellers/Show`, `Support/Show`: identity
   `PageHeader`, `DetailSection` instead of card grids, destructive actions
   (`Terminate` on the service page, void/refund on invoices and orders — 3
   solid `danger` buttons remain in page bodies) into Danger Zones.
2. **List pages to the Clients pattern** — Services, Domains, Orders,
   Invoices, Transactions, Tickets, Staff: `FilterBar`, meta line, priority
   columns, remove hand padding from cells (275 `<td … px-4 py-2.5>` remain;
   harmless but they ignore density).
3. **`AppCard` used as grouping** — 64 page files; worst: Settings (8),
   Invoices/Show (8), Support/Create (7), Orders/Show (7), Customers/Create (7).
4. **Remaining arbitrary type** — `text-[1.5rem]` ×6 (money totals),
   `text-[10px]` ×3, `text-[11px]`, and `text-base/xl/2xl` on client and auth
   screens: move to `text-page` / `MetricStrip`.
5. **Staff two-factor on/off** shown as a coloured badge — make it text or
   `AppStatus`.
6. **Translations** — done for the three reference screens and the new
   primitives. Most other admin pages still hard-code English (the tracker's
   i18n column); convert them as they are redesigned. The shared primitives
   (`AppConfirm`, `AppPagination`, `AppSelectionBar`, `AppTable`,
   `LoadingState`, `ErrorState`) read `ui.*` with an English fallback.
7. **Customer 360** — services, domains, invoices and tickets counts/links
   and a unified timeline on `Customers/Show` need controller data.
8. **Not verified in this pass**: tablet/phone widths (< 1024px) with a real
   resize, a screen-reader run, 200% zoom.
